# 阶段 01：代理池取用模块

## 背景思考

阶段 00 确立了网关定位：完全禁用本地直连，只经 proxy-pool 的免费代理转发到
OpenCode AI 免费模型。本阶段实现第一个核心能力——**代理池取用**：
从 proxy-pool 按 stable 档位降级链取 IP，并对每个 IP 做"能否连通上游 zen"
的筛选，进程内缓存可用代理。

用户拍板的关键约束：
- **完全禁用本地直连**：即使服务器 IP 当前能用，也必须走代理（已知单 IP 有日上限）。
- **档位降级链**：stable3 → stable2 → stable1，全无则停止服务（宁缺毋滥，
  不用不稳定的代理——免费池里质量差的反而暴露/失败率高）。

## 完成内容

### 目录结构
```
app/
├── config.py                 # Settings 集中配置（环境变量 + 构造覆盖）
├── core/
│   ├── proxy_pool.py         # 代理池取用：取IP + 连通性筛选 + 缓存
│   └── model_map.py          # 对外伪名 → 内部真实模型映射
├── services/
│   └── upstream.py           # 上游转发器（走代理，限流换代理重试）
├── api/
│   └── routes.py             # /v1/models /v1/chat/completions /health
└── main.py                   # FastAPI 入口
```

### ProxyPool 核心逻辑（app/core/proxy_pool.py）
1. `get_proxy()`：优先用进程内缓存；缓存过期/为空则刷新。
2. `_refresh()`：遍历档位降级链（stable3→2→1），对每档调 proxy-pool `/get`
   批量取候选，做连通性筛选，第一个非空档即停止降级。
3. `_fetch_candidates()`：调 `{PROXY_POOL_URL}/get?need=global&type=https
   &count=N&quality=stableX`。
4. `_probe()`：对候选 IP 请求上游 `/models`，200/401/403 都算连通
   （401/403 表示代理能到上游，只是该路径对某些模型无认证）。
5. 并发探活：`asyncio.Semaphore` 限并发，避免瞬间打爆上游。

### 模型映射（app/core/model_map.py）
- 对外伪名 → 真实模型：`gpt-4o-mini` → `deepseek-v4-flash-free` 等。
- 客户端只可见伪名，`/v1/models` 只列伪名，不暴露真实模型/品牌名。
- 未知模型名 → 404。

### 转发器（app/services/upstream.py）
- `chat()`：把客户端 body 经模型映射替换 model → 取代理 → 走代理 POST 上游。
- 每次请求构造唯一 `x-opencode-request/session` 头（上游按 IP + 请求头限流，
  重复请求头会被拒）。
- `health()`：网关自检——代理池有无可用 + 经代理探活上游。

## 技术决策及理由

1. **连通性筛选放在"取用侧"而非"转发侧"**：取 IP 时就筛掉连不上上游的，
   转发时直接可用；代价是每次刷新多一次探活，但换来转发高成功率。
2. **缓存 TTL（默认 120s）**：免费代理短命，TTL 太长老化快，太短频繁探活
   消耗上游。120s 平衡：转发频繁时避免反复取 IP。
3. **探活端点用 /models 而非实际 chat**：轻量、无成本、不消耗模型配额，
   只验证"网络层连通"（免费代理基本验证的是可达性而非模型权限）。
4. **档位链在 refresh 时一次性确定**：某档有货就用该档全部候选缓存，
   保证批内一致性；不混档（避免同一批里既有 high 又有 low quality）。

## 踩坑记录

- **服务器 python3.12 无 venv**：`python3.12-venv` 包未装，ensurepip 缺失，
  无法创建虚拟环境。`sudo apt-get install -y python3.12-venv` 解决。
- **apt 走代理 502**：`/etc/apt/apt.conf.d/99proxy` 写死了
  `Acquire::http::Proxy http://127.0.0.1:7890`，环境变量 unset 无效。
  用 `apt-get -o Acquire::http::Proxy="" -o Acquire::https::Proxy=""` 覆盖。
- **httpx 0.28 API 变化**：`AsyncClient.get()` 不再接受 `proxies=` 参数，
  代理只能在 client 构造时用 `proxy=` 传。每候选 IP 需独立 client。
- **httpx client 重复 `async with` 报 "Cannot reopen"**：同一 AsyncClient
  不能多次进入上下文，长期持有的 client 直接 `.get()`。
- **Settings override key 大小写**：构造参数用属性名（`pool_ttl=30`），
  内部按 `key.lower()` 匹配，避免与大写环境变量名冲突。
- **429 FreeUsageLimitError（核心发现）**：免费代理被上游限流是常态
  （实测 4 个 IP 中 1 个 429）。必须换代理重试，不能直接失败。

## 联调结果（真实 proxy-pool）

- `/v1/models` 只暴露伪名：`gpt-4o-mini` / `claude-haiku` / `gemini-flash`。
- `/health` 经代理探活上游：`{"status":"ok","pool":"ok","upstream":"ok"}`。
- 真实转发：`model:gpt-4o-mini` → 上游 `deepseek-v4-flash-free`，返回真实内容。
- 限流轮换：4 连发全过（每请求换代理，429 自动剔除重试）。
