# 阶段 06/07 — 模型源自动治理 + 工具实测接入

阶段 05 后网关功能完备，但两个问题：

1. **模型硬编码**：3 个模型写死在代码里，上游 free 模型随时上/下架（实测 ling/north

2. **兼容性未实测**：宣称兼容主流工具，但从没用 opencode/Cursor 真实连过。

## 阶段 06：模型源自动治理

### 完成内容

`app/core/model_sync.py` `ModelSync`：后台定时同步 free 模型。

- `_fetch_free_models`：经代理池拉 zen `/v1/models`，筛 `-free` 模型
- `_probe_model`：每个候选做最小 chat 探测（并发限 2）
- `sync_once`：返回 added/removed 差异
- **防误伤摘除**：探测失败的模型（可能限流）不立即摘除，保留旧映射；
  仅当候选列表里消失（真下架）才摘
- **Redis 锁**：多 worker 只让一个执行同步（SET NX 抢锁）

`ModelMapper` 改造：映射落 Redis 共享（`models:map` JSON），多 worker 一致。
路由读共享 mapper。

### 实测

- 自动发现 7 个 free，探测通过 4-5 个（含 laguna、nemotron）
- ling/north（下架）自动排除
- 多 worker 下 `/v1/models` 与 `/v1/chat/completions` 一致
- 新增 laguna 模型 chat 可用（Poolside AI）

### 踩坑

1. **RedisStore.get 强制 int 导致 JSON 解析崩**：`models:map` 存 JSON 字符串，
   `get` 应返回原始值，int 需求处调用方转换。
2. **sync_once 全失败清空映射 bug**：一次同步遇全限流 `available=[]`，
   `set_models({})` 把好模型全删。修复：仅候选消失才摘，临时失败保留。
3. **多 worker 各自 mapper 不一致**：`/v1/models` 有 laguna 但 chat 报 Unknown。
   修复：mapper 落 Redis 共享。

## 阶段 07：opencode 实测接入

### 关键发现

opencode 的 `@ai-sdk/openai-compatible` **baseURL 不带 /v1** 时请求
`POST /chat/completions`（而非 `/v1/chat/completions`）→ 404。

**修复**：网关加无版本前缀别名路由（`/chat/completions`、`/models`），
兼容两种 baseURL 习惯。

### 实测结果

- opencode 自定义 provider + baseURL（两种形态都通）→ 正常对话
- **完整 agent 工具调用闭环**：模型调 bash 执行 `echo hello-gateway-test`、
  拿输出、汇报结果——tools 透传 + 多轮 + 流式全链路验证通过
- 三个模型（deepseek/mimo/longcat）在 opencode 下均正常

### opencode 配置示例

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "poverty": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "poverty-gateway",
      "options": {
        "baseURL": "https://api.pixelreeds.com",  // 或带 /v1
        "apiKey": "sk-xxx"
      },
      "models": {
        "deepseek-v4-flash-free": {
          "name": "DeepSeek V4 Flash Free",
          "limit": { "context": 128000, "output": 16384 }
        }
      }
    }
  }
}
```
