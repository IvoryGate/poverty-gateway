# 阶段 10 — 池扩容 / lite 命名 / 冷启动优化

## 背景思考

阶段 09 后服务可用了，但暴露三个问题：

1. **池容量吃紧**：可用池 target 25 时，多 key 并发 + 部分 IP 限流冷却，
   高峰期取号偶发 NoProxyAvailable。
2. **模型名对外显示混乱**：对外叫 `-free`，与 opencode 自带的免费模型重名，
   用户在 opencode 里选模型时分不清、且界面显示成上游真实名。
3. **重启冷启动慢**：重启后可用池从 0 开始重新探测 60 个 IP，
   冷启动要 90s+ 且消耗大量探测请求。

## 一、池扩容 target 25 → 60

### 完成内容

- `pool_target` 25 → 60（zen 可用池目标规模）。
- `pool_low_water` 从固定 12 改为 `int(target * 2/3)` = 40，池掉到 2/3 就补。
- `_refill` 重写为**分批持续补池**：候选按 `probe_batch` 分片循环探测，
  未达 target 继续下一批，直到达标或候选耗尽（不再单批截断）。

### 技术决策

| 决策 | 理由 |
|---|---|
| target 60 + 2/3 低水位 | 池余量足，冷却 30+ 时仍有可用取 |
| 分批持续探测 | 单批 80 不够就补下一批，直到 pool_target 或源耗尽 |
| 探测并发上限 6 | 不把上游打爆，也不让补池拖垮请求响应 |

### 实测

- 单次补池一轮可达 62 个（超出 target 60）。
- 冷却 19-38 个同时 available 仍能维持 40-60，取号不再告急。

## 二、对外模型名 -free → -lite

### 完成内容

- `model_map.py`：`DEFAULT_MODEL_MAP` 对外名改为 `-lite` 后缀，
  内部映射到上游 `-free` 真实名（`deepseek-v4-flash-lite → deepseek-v4-flash-free`）。
- `to_public()`：上游名 `-free` → 对外 `-lite` 自动转换。
- 响应体 `model` 字段统一改写：非流式（`_forward`）+ 流式 SSE
  （`_rewrite_model_bytes` 逐帧替换）都改为对外 lite 名。
- opencode/Cursor 接入配置里的显示名同步为 Lite。

### 技术决策

| 决策 | 理由 |
|---|---|
| 对外 lite / 内部 free | 区分 opencode 自带免费模型，用户界面不再混淆 |
| 响应 model 字段也改写 | 否则客户端 UI 显示上游真实名（free），对内对外不一致 |
| 流式逐帧替换而非整流缓冲 | 不影响吞吐，SSE 帧边界完整替换 |

### 踩坑

1. **只改请求头不够**：最初只改请求 `model` 名，客户端仍显示 free——
   因为响应 body 里 `model` 字段是上游真实名，要两处都改。
2. **流式替换要按 SSE 帧**：直接字节替换会截断跨帧的 model 字符串，
   必须缓冲到 `\n\n` 完整帧再替换。

## 三、可用池快照落盘（冷启动优化）

### 完成内容

- `RedisStore` 新增 `snapshot_set` / `snapshot_get`。
- `ProxyPool.save_snapshot()`：可用池 JSON 写 Redis（TTL 24h），
  与已有快照取"更大者"防多 worker 覆盖。
- `load_snapshot()`：启动时读回快照，跳过冷启动重探测。
- `main.py` lifespan：启动加载快照；shutdown 保存快照；
  另起 24h 周期快照任务兜底。

### 技术决策

| 决策 | 理由 |
|---|---|
| 快照只存可用池 | 冷却/in-flight 是 TTL 临时态，Redis 天然保存，无需入快照 |
| 取更大者防覆盖 | 多 worker 各自持池，池空的 worker 停机时会覆盖池满的，必须取大 |
| TTL 24h | 池子 IP 会过期/失效，超过 24h 的快照应作废重新探测 |
| 三个时机落盘 | 优雅停机(准) + 24h 周期(兜底) 覆盖异常断电 |

### 踩坑

1. **多 worker 覆盖 bug**：worker A 存 46 个 → worker B（池空）存 1 个覆盖，
   最终快照只有 1 个。修复：保存前与 Redis 已有快照比大小，取更大者。
2. **`REDIS_URL` 由 systemd 注入**：本地测试直接跑 Settings 时 redis_url 为空
   走内存态，必须带 `REDIS_URL=redis://127.0.0.1:6379/1` 才连真实 Redis。

### 实测

- 重启前池 59/45 → shutdown 保存 60 个快照 → 重启后两 worker
  available=60、refill=0，**秒级恢复，零探测、零额外 IP 消耗**。
- 对比改造前：冷启动重新探测 60 IP 需 90s+。
