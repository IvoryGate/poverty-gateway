# 阶段 17 — 池扩容 + 延迟/稳定性强化：吃透上游 2300+ 供给

## 背景思考

proxy-pool 阶段 17 接入全球大源后池子从 160 → 2300+（18 倍）。网关侧仍守着
阶段 16 的旧参数（pool_target 90、probe_batch 60、probe_concurrency 8），
只用了 3% 的候选供给。同时真实流量暴露质量问题：

- 错误构成里 **timeout 95 / conn 34** 居高——大量慢/挂代理被选中，拖垮请求；
- 延迟中位数已到 **7s**，缺"质量下限"（慢的不剔除、只排后面）；
- 免费代理短命，"验证过"≠"现在还活着"，可用池里可能囤积"放久了变僵尸"的
  占位（正分但已失效）。

用户核心诉求：**池子涨了，网关要对应强化——扣质量、扣延迟、扣稳定性、扣并发，
甚至用真实请求做测试保证通畅**。

## 完成内容

### 1. 池扩容（吃透上游供给）
- `pool_target` 90 → **150**（更多已验证 IP 缓冲，分摊 429 与延迟）
- `probe_batch` 60 → **120**（单轮补池筛更多候选）
- `probe_concurrency` 8 → **12**，`_refill` 内硬顶 10 → 20（消化 2300+ 候选）

### 2. 延迟扣质量：选号硬上限过滤（max_latency_ms）
`get_proxy()` 选号在"正分分档"前新增延迟过滤：
- 已知延迟 **≤ 15000ms** 的 IP 才能进候选（默认 `MAX_LATENCY_MS=15000`）；
- 有达标 IP 时超上限的直接剔除（宁缺毋滥）；
- 全部超标时兜底选"最不慢"的（总比 503 强）。

之前只有"按延迟排序、慢的排后面"——慢/挂代理仍会被选中；现在有质量下限。

### 3. 稳定性强化：闲置成员真实请求 spot-check（stale 重验）
`_reverify_pool_members()` 从"只验非正分"扩展为**两类成员都真实探测**：
1. 非正分成员（从未验证/历史失败）——沿用；
2. **正分但闲置过久**（超过 `stale_after_s=900` 未被真实请求/探测命中）——
   按"最久没用"优先，每轮最多抽查 `stale_check_batch=30` 个。

这正是用户要的"用真实请求做测试"：免费代理短命，闲置的 IP 重新跑一次最小
chat 探测，OK 保留/429 冷却/DEAD 剔除，保证池子里没有"放久了变僵尸"的占位。
每个新 IP 探测通过即记录 `_last_used` 时间戳，取号/真实成功也会更新。

## 技术决策及理由

- **延迟过滤选"有达标就剔除，全超标就兜底"而非"一律不选"**：纯宁缺毋滥会
  在池子整体变慢时把服务打成 503；兜底选最不慢的更稳。
- **stale spot-check 放 `_reverify_pool_members` 而非独立周期任务**：它本来就
  在每次补池开头跑，复用补池的并发信号量，不新增调度器复杂度；`stale_check_batch`
  限制每轮烧探测额度，避免一次重验几百个。
- **`_last_used` 用进程内 dict**：跟 `_latency` 一致（探测/取号/报告都是本进程
  触发的），多 worker 各记各的，不影响正确性（某 worker 的闲置 IP 由别的 worker
  重验同样有效，只是池子快照互通时 `_last_used` 会重置，可接受）。

## 实际命令

```bash
# 测试（67 全过）
cd /home/matrix/Desktop/poverty-gateway && .venv/bin/python -m pytest -q

# 验证

```

## 踩坑记录

1. **`_reverify_pool_members` 扩逻辑时差点误删正分成员**：原实现只收集非正分；
   扩展后正分闲置成员也会被探测，若探测结果 DEAD 会被剔除——这正是想要的
   （僵尸清洗），但要靠 `stale_after_s` 限频，不能每轮全量重验（会烧额度）。
2. **测试 `stale_cap` 排序方向反了**：最早写的测试用"时间越早越大"，断言最久
   的优先，实际验证发现断言取错；修正 `_last_used` 赋值方向后通过。

## 成果

- 网关可用池目标 90 → 150，探测并发/批量同步提升，吃透上游 2300+ 供给。
- 新增质量下限：选号过滤超 15s 慢代理（从"排序"升级为"硬剔除"）。
- 新增稳定性机制：闲置 15 分钟的代理真实请求重验，僵尸无法长期占位。
- 67 测试全过 + ruff 全过。
