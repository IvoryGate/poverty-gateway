# 阶段 00：项目初始化

## 背景思考

用户已有 proxy-pool（免费 IP 池，Docker 化部署在服务器上），想要一个"零成本 LLM
网关"：用池子里稳定的免费代理 IP 去请求 OpenCode AI 的免费模型（deepseek-v4-flash-free），
对外提供 OpenAI 兼容接口，接入 Cursor / Codex / Continue 等工具自用。

关键背景（调研结论）：
- 服务器本机 IP 直连 opencode.ai/zen 免费通道**能通**（无认证、无 token 限制、当前只受 IP 级限流）。
- 但用户要求**完全禁用本地直连**：已知单 IP 有日用量上限，必须通过代理 IP 分散请求。
- 免费代理质量参差，所以要选 **stable 档位**（信任分高 = 通过多次验证 = 更稳定更匿名）。

## 完成内容

- 建立项目目录骨架：`app/{core,api,services}` / `tests` / `docs` / `.github/workflows`。
- 复制 proxy-pool 的 `engineering-discipline` skill 到本项目 `.opencode/skills/`。
- 编写 `AGENTS.md`：项目定位、核心约束、运行命令、工程纪律约定。
- 编写 `docs/PROGRESS.md` 总索引。

## 技术决策及理由

1. **项目命名 poverty-gateway**：避开 zen 等第三方品牌名（用户要求，避免商标/品牌混淆）。
2. **同机部署**：网关和 proxy-pool 在同一台服务器，直接内网 `127.0.0.1:5010` 取 IP，
   省去跨机网络与鉴权。
3. **技术栈 FastAPI**：Python 与 proxy-pool 同语言、可复用经验；async 高并发适合网关转发。
4. **完全禁用直连**：用户明确要求——即使本机 IP 当前可用，也必须走代理，保证未来不触顶。
5. **stable 降级链 3→2→1，全无停服**：宁缺毋滥，不用不稳定的代理（免费代理里质量差的
   反而会暴露/失败率高）。

## 踩坑记录

- 服务器 git push 403：`IvoryGate/proxy-pool` 的推送凭证在服务器上无权限
  （credential.helper=store，但存的是只读/过期 token）。不影响运行，后续需换 token。
- proxy-pool 的 Dockerfile 依赖走清华 PyPI 镜像（服务器直连 PyPI 极慢），已提交本地。
