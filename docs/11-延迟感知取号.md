# 阶段 11 — 延迟感知取号（生产流量当探测）

## 背景思考

池子扩容（阶段 10）之后容量不再是瓶颈，但暴露一个新问题：

1. **慢 IP 拖后腿**：可用池里混着快慢不一的 IP，
   快的 ~2.8s、慢的要 90s+，取号随机时会随机踩到慢 IP。
2. **探测成本高**：想按延迟排序就得频繁探测每个 IP，
   但探测 = 额外请求上游（消耗免费额度 + 上游可能限制），不划算。
3. **更好的思路**：反正每次真实请求都要经过代理 IP，
   顺手把**实际耗时**记下来，用生产流量当探测 —— 零额外成本。
   冷启动时没有真实数据，探测顺带测速兜底。

## 一、实现内容

### 延迟表（EWMA）

- `ProxyPool.__init__` 新增 `self._latency: dict[str, float]`（毫秒）。
- 新增 `_update_latency()`：EWMA 平滑，α=0.3 偏重近期，防单次抖动。
  ```python
  def _update_latency(self, proxy: str, latency_ms: float):
      prev = self._latency.get(proxy, latency_ms)
      self._latency[proxy] = round(0.3 * latency_ms + 0.7 * prev, 1)
  ```

### 取号排序

- `get_proxy()` 的 pick 从「最空闲优先」升级为
  「**最空闲优先，同空闲取延迟低**」：
  ```python
  min(candidates, key=lambda p: (in_flight(p), self._latency.get(p, 0.0)))
  ```
- 无延迟数据（冷启动）时 `get(p, 0.0)` 兜底，行为与原来一致。

### 真实请求回写

- `report()` 签名增加 `latency_ms: float = 0.0`，OK 且 >0 时更新延迟表。
- 接入点：
  - **非流式 `_forward`**：`_request` 前后计时，OK 传总耗时。
  - **流式 `_forward_stream`**：传**首字节延迟 TTFB**（首个 chunk 到达耗时），
    这是上游响应快慢的核心信号；后续耗时被生成速率主导，无意义。

### 探测顺带测速（冷启动兜底）

- `_probe()` 加 `time.monotonic()` 计时，探测 OK 时也更新延迟表，
  新池子一上来就有排序依据。

### 可观测性

- `metrics()` 增加 `latency_median_ms`（延迟表中位数）与 `latency_sampled`（采样数），
  面板 /v1/stats 可直接看延迟排序有没有生效。

## 二、技术决策

| 决策 | 理由 |
|---|---|
| 生产流量当探测 | 请求反正要过 IP，零额外上游请求、零额外额度消耗 |
| EWMA α=0.3 | 偏重近期，慢转快/快转慢都能快速跟上，又不被单次毛刺带偏 |
| 取号按 (in-flight, latency) | 先保证不把负载集中到同一 IP，再选快的 —— 兼顾均衡与速度 |
| 流式用 TTFB 而非总耗时 | 总耗时含生成时间（token 越多越久），TTFB 才是纯延迟信号 |
| 中位数而非均值 | 慢 IP 的极端值会把均值拉高，中位数更能代表"典型体验" |

## 三、踩坑记录

1. **流式重复 report(OK)**：原代码在首字节 report 一次 + 流结束后又 report 一次，
   导致 in-flight 双归还、计数错误。修复：只在首字节 report，流结束只 return。
   空流（零 chunk）的边角情况保留一次 OK 兜底归还。
2. **编辑事故**：改流式路径时误删了 `for attempt in range(MAX_RETRIES)` 循环头、
   还有 `ttf b` 拼写错误。靠 read 校对 + pytest 兜住，最终 48 passed。

```bash

# 发 4 个真实请求积累延迟数据

```

## 五、实测结果

- 4 个真实请求全 200，首个请求 13.9s（冷代理热身，快照里的 IP 无延迟数据兜底），
  后续稳定 3.5-4.3s。
- `latency_sampled: 5`、`latency_median: 4249ms` —— 延迟表在真实流量下持续积累。
- 慢 IP 自动排后、快 IP 优先取号，完全靠生产流量驱动，**零额外 IP 消耗**。
- 48 测试 + ruff 全过。
